1. 怎么让Agent获取上下文？

不要一次行塞给智能体，要按需获取，分层展开。
Claude Code最初用的RAG，代码库建立向量索引，然后再塞到上下文中去，后来去掉了。既然Claude Code都能去搜索网络，为什么不能去搜索代码库呢，这样可以更精致的搜索，又可以防止冗余信息的干扰。

之前的Claud Code不会去找自己的上下文，现在能够跨多个文件进行嵌套搜索，找到所需的确切上下文。让它自己去搜上下文，它可以更精准。

2. 怎么扩展Agent的能力？

Claude Code本身并不知道如何去使用自己，要不要给他加一个说明文档呢？

但每多加一个工具，模型在推理的时候就会多加一个选项，要去权衡，如果把使用文档塞到系统提示词里，大部分时间都是用不到的，会造成这个上下文信息的命中率很低，且会导致上下文污染和干扰。

子agent、文件引用、让agent在需要的时候自己去发现自己有这样的能力。

3. 旧能力应该在什么时候被吓掉

随着模型能力的提升，模型曾经需要的工具现在可能反而会限制它们的发展，依靠模型的能力就能处理的很好。

4. 自己搭建智能体的思路
工具要少而精，一开始只给必要的工具，同时给核心的工具加一个搜索或者发现的途径或者入口。
比如 做一个延迟加载的机制设计，智能体如果需要就可以通过搜索的方式发现并加载需要的工具。
扩展能力优先去考虑文件引用和子代理，而不是一直往里面加工具。
定期去审视你的工具集，三个月前模型需要的工具在现在可能不需要了
塞得越多，越受限。给的越克制，模型反而发挥的越好。
