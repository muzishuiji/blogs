1. 怎么让Agent获取上下文？

不要一次行塞给智能体，要按需获取，分层展开。
Claude Code最初用的RAG，代码库建立向量索引，然后再塞到上下文中去，后来去掉了。既然Claude Code都能去搜索网络，为什么不能去搜索代码库呢，这样可以更精致的搜索，又可以防止冗余信息的干扰。

之前的Claud Code不会去找自己的上下文，现在能够跨多个文件进行嵌套搜索，找到所需的确切上下文。让它自己去搜上下文，它可以更精准。

2. 怎么扩展Agent的能力？

Claude Code本身并不知道如何去使用自己，要不要给他加一个说明文档呢？

但每多加一个工具，模型在推理的时候就会多加一个选项，要去权衡，如果把使用文档塞到系统提示词里，大部分时间都是用不到的，会造成这个上下文信息的命中率很低，且会导致上下文污染和干扰。

子agent、文件引用、让agent在需要的时候自己去发现自己有这样的能力。

3. 旧能力应该在什么时候被吓掉

随着模型能力的提升，模型曾经需要的工具现在可能反而会限制它们的发展，依靠模型的能力就能处理的很好。

4. 自己搭建智能体的思路
工具要少而精，一开始只给必要的工具，同时给核心的工具加一个搜索或者发现的途径或者入口。
比如 做一个延迟加载的机制设计，智能体如果需要就可以通过搜索的方式发现并加载需要的工具。
扩展能力优先去考虑文件引用和子代理，而不是一直往里面加工具。
定期去审视你的工具集，三个月前模型需要的工具在现在可能不需要了
塞得越多，越受限。给的越克制，模型反而发挥的越好。


5. Claude Code的记忆系统

  1. 指令记忆 - 规则级    CLAUDE.md 文件族；
  多层级优先级递增的静态指令加载系统。claude.md 的分层加载的设计很像npm包的node_modules 的分层加载设计；
claude.md 还支持@ 引入其他的md文件，同时做了处理循环依赖的设计，可以让你模块化的管理claude.md 文件。（同时支持设置命中和匹配规则，设计的很细节。）
claude code的指令记忆，不是一次性加载的，而是按需的，分层注入的。
对于指令记忆的注入，claude code也是采取了双轨注入架构：
    - 通道A：指令记忆  用户编写、多变、频繁更新
    claude.md 文件族 -- getClaudeMds() -- 作为首条use rmeta message
    - 通道B：行为规范  系统内置、稳定、缓存复用
    memdir行为规范（约束指令记忆的分层策略和加载策略） -- systemPromptSection（） -- system prompt 
  2. 短期记忆 - 会话级    每次的完整对话历史；
  存在内存里的会话级别的短期记忆，会随着会话结束丢失。
  3. 工作记忆 - 任务级    进度/偏移/投机；
  跟当前正在执行的任务相关，比如进度/偏移量/投机响应状态等。
  4. 长期记忆 - 持久级    memdir 知识库（最核心）；
  基于磁盘上的markdown文件，构建了一份分层的知识库引擎。系统会自动在你的工作空间下创建专门的记忆文件夹。按照用户画像、行为反馈，项目上下文、外部引用这四种类型来组织知识。
  记住什么，不记住什么，claude code约定了四种类型的数据被记住：
    - 用户画像：存储偏好语言、工作风格、经验水平；
    - 行为纠正/确认：双向记录：错误纠正 + 成功确认；
    只记录错误，就让ai变得过度保守。也要记录成功，告诉ai继续这样做。
    - 项目上下文：项目技术栈、架构约定、文件结构；
    - 外部指针：指向外部文档/URL的指针索引；
  什么不能存：代码模式、架构分析、文件路径、GIT历史、调试方案等，这些基本都能推导出来。
   

   两层结构：
     - memory.md 只存索引，每行就是一个指向具体记忆文件的链接加上一句话摘要（不超过150字符）。
     - 异步预取流程：与模型并行执行，不阻塞主流程
     对话开始 -- 异步prefetch -- 扫描md文件 -- 提取描述信息
     让sonnet做一次智能筛选，判断哪些记忆和当前话题最相关，并制定相关的筛选规则；
     用轻量级模型来做智能筛选，既保证了选择质量，又控制了成本。
    - 记忆新鲜度系统：回来标记记忆新鲜度。
    - 记忆自动提取：对话相应完成后，主agent不会自己处理记忆，而是fork出一个子agent来处理，专门来同步最近的对话内容，把长期保留的信息提取出来写入记忆文件。这里还会处理和主agent的写入冲突和权限控制。
    

  5. 摘要记忆 - 压缩级    session memory；（每次会话结束都生成一份摘要）；
  当对话太长，token要爆的时候，系统会触发压缩。但claude code不是简单的让llm生成一段摘要就完事了。它引入了一个session memory的机制，然后通过子代理持续维持一份会话笔记。压缩的时候直接用这份会话笔记替代临时生成的摘要。

  session memory 机制：开始时就开始收集，随着对话更新；压缩保留哪些信息：确保工具调用完整性、确保thinking block的关联机制不被破坏。
  6. 休眠重塑 - 离线级    AutoDream； （每一段时间都会做）
  自动做梦，当满足一定时间和会话次数的条件后，系统会自动启动一个整合流程，把碎片化的记忆清理、合并、去除矛盾，然后更新全局索引。
  触发的前提：距离上次整理过去了24小时，且期间至少有5个不同的会话产生了新的记忆。
  整合：重量级操作，需要扫描记忆文件、读区转录日志、分析矛盾、合并重复。
  整合流程：
  定向探索（浏览记忆目录，检查索引，发现重复） -- 信息收集（查看日志，检查矛盾，再搜索转录） -- 整合（合并到现有主题，相对-绝对日期，删除旧事实） -- 修剪索引（200行，150字符行，解决矛盾），模拟人类整理笔记的思维过程。
